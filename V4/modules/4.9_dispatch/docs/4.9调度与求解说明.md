# 4.9 约束条件与求解方法：V4纳入说明

## 当前执行链

```text
4.3源侧边界 + 4.5状态/构网备用边界 + 4.6算力边界
        ↓
4.9生成第一轮逐时REQUEST
        ↓
4.3—4.7返回accepted/actual
        ↓
4.9检查偏差并按剩余边界再调度
        ↓
4.3—4.7返回最终accepted/actual
        ↓
4.9确认实际弃电和分类缺供并COMMIT
        ↓
4.4仅用actual核验物理总账
        ↓
4.8评价
```

4.5和4.6均不再在4.9之前完成固定响应。4.5先发布显式SOC、储氢库存、可充/可放能力、构网备用、站损和终端规则；4.9生成逐时电池、电解槽、提氢和算力请求；4.5/4.6再返回物理响应。

4.9只消费调用方显式传入的4.5 BOUNDARY。缺少该包时直接报错，不允许回退到`cfg`初值，也不允许在4.9内部隐式调用4.5参数overlay。这样，滚动窗口的期初状态和约束口径均由4.5包唯一确定，避免4.9与4.5各自维护一套参数。以原始冻结4.2配置直接调用4.9、同时传入完整4.5 BOUNDARY的隔离回归已经通过。

当前算法标识为`FEASIBILITY_RULE_V4_4_9`，只形成可行请求，不形成Pareto或全局最优性结论。当前已实现4.6响应后、4.7请求前的顺序再调度：若任务可行域使数据中心实际功率低于请求，释放功率依次进入海洋需求缺口、海缆剩余送出能力、同小时直通制氢，最后才形成弃电。其余模块若仍存在响应偏差，则必须继续执行第二轮，不得把偏差直接记为弃电。

## 当前优先规则

1. 电池在预留构网功率/能量并具备窗口末点约束可修复条件后，支撑共同辅助、显式声明的`computeFirmRequestMW`及海洋刚性负荷；
2. 算力默认是柔性负荷，请求只能为0或不低于在线最低功率，资源不足时停机并由4.6记录任务SLA缺口；
3. 在已申报海洋服务需求得到分配后，剩余电力先用于电池充电，再启动柔性算力；
4. 储氢库存不足以覆盖当期合同提氢上限时，先安排满足最低运行功率和储罐空间约束的补产；
5. 合同补产之外的富余电力继续比较氢的净边际价值`1000×(氢价−单位变动成本)/SEC`与海缆送端对应的到岸电力价值`电价×(1−海缆损失率)`，价值较高的通道优先，电解槽可由0升至额定功率；
6. 电池、算力、海洋负荷、海缆和电解槽均无可用向上能力后才允许弃电。

合同提氢量和非公开成本仍为 **[假设值，待企业调研校准]**。氢价采用上海环境能源交易所公开指数、年度电价采用国家能源局广东日前均价作为情景锚点，但均不是企业已签认的结算价格。当前价值比较仍是可行启发式，不构成全局最优性结论。

## 电池与储氢的路径和期末约束

`cyclic`与`minimum/cyclic_or_minimum`是窗口末点约束，不是逐时库存下限。调度路径本身只执行物理边界：

- 电池能量下界为`SOCmin×额定能量+构网备用能量`，上界为`SOCmax×额定能量`；
- 储氢库存下界为0，上界为储罐容量；
- `cyclic`要求窗口末点回到由4.5 BOUNDARY给定的期初状态；
- `minimum`要求窗口末点不低于4.5 BOUNDARY给定的目标；
- `free/free_with_terminal_value`不在当前确定性规则中提供长期可比性保证；当前4.9尚未计算终端价值。

在初始逐时分配后，4.9执行确定性期末修复：

1. 电池期末能量不足时，按可用充电功率和后续能量上界，优先将已有弃电转为充电，其次缩减外送并转为充电；
2. 电池期末能量过高时，移除部分既有充电，并把释放功率转为未满的海缆外送，剩余部分记为弃电；
3. 每次调整后重新计算完整电池能量路径，并同步修正外送/弃电，保持电池递推和逐时母线守恒；
4. 储氢期末库存不足时减少可调整的氢气交付，库存过高时在交付目标和通道余量内增加交付，并重新计算完整库存路径；
5. 任一路径无法在物理边界内满足窗口末点规则时，返回`terminalOK=false`，验证器将其作为硬错误拒绝提交。

上述过程是可解释的可行性后处理，不是混合整数优化器，也不保证系统成本或收益全局最优。

验证器不直接相信调度器携带的状态数组，而是从4.5 BOUNDARY期初状态出发，分别复算：

```text
电池：期初能量 → 站损保留 → 充电效率计入 → 放电效率扣除 → 逐时能量
储氢：期初库存 → 储存损失 → 电解制氢计入 → 氢气交付扣除 → 逐时库存
```

复算路径必须与调度计划逐点一致，且末点必须满足对应`cyclic/minimum`规则，否则4.9硬报错。

## 算力响应后的同小时再调度

4.6可能因任务粒度、在线最低功率或SLA可行域约束，使实际算力功率低于4.9请求。释放功率按以下顺序处理：

```text
算力释放功率
  → 补足已申报的海洋用能缺口
  → 利用海缆剩余送出能力
  → 在电解槽额定功率、启机最低功率和当期提氢余量内直通制氢
  → 仍无法吸收的部分形成弃电
```

直通制氢的新增产氢量在同一小时等量增加提氢量，因此新增产氢与新增交付在库存递推中相抵；它不会改变原计划储氢库存路径，也不会改变储氢期末约束。响应后二次分配仍须满足功率分配恒等式。

## 缺供与功率平衡口径

- `marineRequestedMW`表示完整海洋需求；
- `marineAllocatedMW`表示4.9可分配给4.7的功率；
- 4.7返回`marineActualMW`和`marineUnservedMW`；
- 算力电气功率缺口与任务SLA缺口分别记账：前者为MW/MWh，后者为MWh-CS；
- 缺供是可靠性KPI，不进入4.4功率平衡式充当虚拟注入；
- 4.9根据实际响应计算`spillMW`，4.4只负责核验残差。
- 任一时段若`spillMW>0`且仍有可调电负荷缺供，4.9拒绝提交并要求再次请求；不可转移的任务SLA违约不与电力弃电直接比较。

## 已执行约束

- 4.6边界先于4.9请求、响应后于4.9请求；
- 显式继承4.5 BOUNDARY期初SOC和储氢，禁止窗口内重置；
- 电池SOC、能量、充放功率、充放互斥及构网备用功率/能量；
- 电池路径仅执行SOC/构网备用物理边界，`cyclic/minimum`只执行窗口末点硬约束；
- 储氢路径仅执行0—储罐容量物理边界，`cyclic/minimum/cyclic_or_minimum`只执行窗口末点硬约束；
- 算力设施0/在线最低功率互斥、SLA主模型与功率跟随上界模式区分；
- 电解槽额定功率及5×20 MW模块化4 MW最低非零功率；模块独立启停为 **[假设值，待OEM/BOP确认]**；
- 逐时制氢—提氢—库存递推、储罐时末边界和通道能力；
- 海洋刚性/柔性需求及未供量；
- 海缆送端容量和陆上受端容量；
- 计划闭合、响应后实际弃电及4.4实际总账。

## 专项回归验收

`test_v4_post_compute_redispatch_4_9.m`的6项检查已通过，覆盖：

1. 算力释放功率按海洋缺口、海缆余量和直通制氢依次分配；
2. 离线电解槽拒绝低于启机最低功率的增量；
3. 已在线电解槽可接收未超过额定值的增量；
4. 提氢通道饱和后剩余功率正确进入弃电；
5. 同小时增产与新增提氢相抵，储氢库存路径不变；
6. 响应后二次分配功率恒等式闭合。

`test_v4_terminal_path_rules_4_9.m`的期末路径核心5项已通过：电池可在中间时段低于循环目标、末点精确恢复；储氢可在中间时段低于循环目标、末点精确恢复；两条修复路径均保持物理边界。另有“4.9直接消费显式4.5 BOUNDARY、无overlay耦合”的隔离检查通过。

上述检查结果属于 **[模型仿真结果]**；测试中的出力、负荷、容量和价格均为 **[假设值，待企业调研校准]**。
