## 2. GitHub 数据集核查结论

可用于后续替换合成任务曲线的公开生产数据包括：

- `Azure/AzurePublicDataset`：微软公开的 VM、Functions、LLM/LMM 推理调用轨迹；来源类型为企业官方 GitHub 数据集。
- `alibaba/clusterdata`：含 2020/2023 GPU 集群轨迹、在线服务与批任务；来源类型为企业官方 GitHub 数据集。
- `google/cluster-data`：Borg 集群负载和 2019 电力轨迹；来源类型为企业官方 GitHub 数据集。

本次没有把上述轨迹直接覆盖 `green_compute_v1_168h.csv`。它们反映云厂商生产集群，不等于本项目的客户签约量、业务类型占比和海缆时延条件；直接替换会把“公开生产轨迹”误当成“项目需求预测”。现有 168 h 到达曲线因此继续标记为 **[假设值，待企业调研校准]**。下一步应建立单独的 `public_trace` 情景，经重采样和容量缩放后用于稳健性测试，不作为基准商业预测。

## 3. 仍未解除的假设

以下参数没有可直接迁移的同口径公开实测数据，继续保留 **[假设值，待企业调研校准]**：

- 7.08 MW IT 容量、180 机柜及具体服务器 BOM；
- 空载功率比、配电效率、最低负载率；
- 固定冷却功率、温度系数、热惯性时间常数及二次功率曲线；
- 刚性/柔性任务比例、到达量、最大延迟、连续运行时间和 SLA 违约金；
- 海底舱体、服务器、网络、光模块、运维船舶、保险、备件和更新改造 CAPEX/OPEX；
- 面向大客户的批发折扣、平台抽成、税费、带宽费和售前售后成本。

当前 PUE 曲线是“公开 PUE 锚点 + 工程代理曲线”。曲线形式及冷却系数没有完成论文或设备实测验证，统一标记 **[需查证文献支撑]**。

## 4. 成本收益口径修正

按 1.275 kW/GPU 的公开代理值，1 MWh-IT 对应约 784.31 GPU·h。当前公开报价折算的毛收入参照为：

| 任务情景 | 折算毛收入（元/MWh-IT） |
|---|---:|
| H20 刚性推理 | 5,945.10 |
| A800 柔性批处理 | 3,905.88 |
| H800 连续训练 | 6,964.71 |
| RTX 5090 可选任务 | 2,180.39 |

因此，4.8 原固定 `500 元/MWh-CS` 与当前公开市场租价不匹配，低约 4.4—13.9 倍。本次集成已改为优先读取 4.6 按任务逐时计算的毛收入、SLA 罚金和可变运维费；500 元/MWh-CS 仅保留为脱离 4.6 单独运行 4.8 时的未校准回退值。

4.6 中的电费属于内部转移价/机会成本。4.8 已在源侧计算发电成本，因此不得再次把该电费加入项目总成本，否则会重复计费。4.8 现在只把算力毛收入计入收入，把 SLA 罚金和算力可变运维计入成本，并把内部电费单独披露。

## 5. 市场匹配结论

更新后的“单价与硬件功率代理”已与当前公开市场参照基本对齐，但仍只能形成算力业务的边际贡献分析，不能形成项目财务可行性结论。原因是 `variable_om_yuan_per_mwh_it` 仍为 0，且 4.8 的算力 CAPEX、折旧、融资、带宽、人员、备件、保险和设备更新成本尚未校准。

在企业报价和 BOM 到位前，报告中应使用“公开零售报价情景”“内部转移价情景”“未计完整 CAPEX/OPEX”，不得表述为锁定合同价、净利润、IRR 或投资回收期。
