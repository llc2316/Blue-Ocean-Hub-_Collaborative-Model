# 4.7 多形态输出

- `delivery_model/`：原电力、氢、算力和海洋交付代码、配置、示例与测试。其中只有
  `power_export.py`和`marine_load.py`由V4正式桥接器调用；其余重复功能仅供原生测试与追溯。
- `integration/v4_output_bridge.py`：V4正式桥接，分别接收海洋完整需求和4.9可分配功率，返回实际服务、刚性负荷状态和未供能；同时调用海缆外送并接收4.5/4.6已完成的产品或服务量。
- `docs/`：工程使用说明。

`delivery_model`中重复的PUE、制氢库存、全系统平衡和总目标函数仅保留用于原生测试与追溯，V4联合入口不调用。

## V4正式责任

| 产品/服务 | 上游生产或状态责任 | 4.7责任 |
|---|---|---|
| 电力 | 4.3供给、4.9分配 | 海缆容量、受端电量和损耗 |
| 氢气 | 4.5制氢与库存 | 管道/船运提取、损耗和交付量 |
| 算力 | 4.6 PUE、任务、队列和服务量 | 光缆交付能力与最终交付量 |
| 海洋用能 | 4.9分配 | 需求服务、刚性状态和未供量 |

4.7不负责跨模块优化、不重算制氢、不重算PUE、不建立第二套母线总账，也不生成4.8总目标。

氢气现分别返回管输/船运的提取量和交付量。提取量用于4.5库存提交，交付量用于4.8收入；
管输与船运损耗及运输成本分别核算，不能把交付损耗后的质量再次从储罐扣减。48小时验证
场景关闭管输、仅启用船运，用于证明船运链路已被实际激活；运力与单位运输成本为
**[假设值，待企业调研校准]**。
