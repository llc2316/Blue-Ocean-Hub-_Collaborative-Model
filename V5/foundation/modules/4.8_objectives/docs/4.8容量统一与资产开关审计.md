# 4.8 容量统一与E/H/C/M资产开关审计

> 修订日期：2026-07-27  
> 适用范围：24 h/48 h机制验证；正式8760 h四方案比较留待第5章。  
> 未签认工程规模：**[假设值，待企业调研校准]**

## 1. 三层容量口径

V4不再用一个字段同时表达“接口能接多少、项目建了多少、调度想用多少”，而是统一拆为：

| 层级 | 字段 | 用途 |
|---|---|---|
| 接口上限 | `cfg.capacity.interfaceLimit` | 校验请求和响应不得越过接口边界 |
| 实际建设容量 | `cfg.capacity.installed` | 物理可运行上限及CAPEX/FOM/替换成本计量基数 |
| 调度请求 | `cfg.capacity.dispatchRequest` | 4.9逐时请求的情景边界，不直接形成资产成本 |

算力进一步记录设施MW和IT MW。当前16个同构单元聚合为121.889280 MW设施容量、
113.28 MW-IT；项目接口上限120 MW。算力CAPEX只按113.28 MW-IT计量。

## 2. 资产开关

| 方案 | 启用的专属输出资产 | 未启用资产处理 |
|---|---|---|
| E | 电力海缆、换流/升压站 | 电解槽、储氢、算力、通信光缆成本为0 |
| H | 电解槽、按工艺缓冲与库存轨迹定容的储氢 | 电力海缆、换流/升压站、算力、通信光缆成本为0 |
| C | 算力、通信光缆 | 电解槽、储氢、电力海缆、换流/升压站成本为0 |
| M | 电力、氢、算力全部通道 | 各资产按实际建设容量和动态储氢容量计量 |

源侧和BESS作为四方案共同基础资产保留。代码验收硬检查
`scenarioEnabled=false`资产的CAPEX、年度FOM和替换成本现值均为0。

## 3. 动态储氢定容

储氢定容顺序为：

```text
额定电解槽与SEC → 最小工艺缓冲量
实际剩余能源 → 电解槽实际功率 → 实际产氢/交付 → 逐时库存递推
→ 最大跨时库存
最终建设容量 = max(最小工艺缓冲量, 最大跨时库存)
```

`storageCapacityKg`只是物理接口上限，不再直接计作已建储罐。当前以1 h额定产氢量作为
最小工艺缓冲下限；100 MW、56.77 kWh/kg对应1,761.494 kg。1 h为
**[假设值，待企业调研校准]**。当前24 h与48 h最大跨时库存均为0 kg，但仍配置上述
缓冲罐并计入CAPEX和FOM。若第5章引入船期窗口后形成更大跨时库存，则自动按更大的库存
轨迹定容；储氢技术、安全裕度和备用系数仍需企业校准。

## 4. 海缆成本边界

电力外送资产分为线路和站端两行。线路CAPEX关联离岸距离、输送容量、电压等级和回路数；
站端CAPEX关联技术路线、电压等级和换流/升压站数量。当前200 km、200 MW场景使用
320 kV HVDC单极、1回路、2座站端代理。

线路、换流站和建设成本来自NREL官方报告：
<https://docs.nrel.gov/docs/fy24osti/88003.pdf>；约80 km交直流筛选参考来自NREL官方报告：
<https://www.nrel.gov/docs/fy25osti/91900.pdf>。回路额定容量、站数及本项目选型均为
**[假设值，待企业调研校准]**。
