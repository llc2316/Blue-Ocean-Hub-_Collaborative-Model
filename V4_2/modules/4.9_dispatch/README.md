# 4.9统一协调调度

当前4.9是`FEASIBILITY_RULE_V4_4_9`确定性可行协调器。它用于生成并校核可行请求，不宣称Pareto最优、随机优化或滚动时域全局最优。

- `model/v4_dispatch_4_9.m`：显式消费4.3、4.5、4.6 BOUNDARY，分配电池、算力、海洋用能、电解槽、海缆和弃电。
- `model/v4_validate_dispatch_4_9.m`：独立复算电池能量和储氢库存两条逐时递推，并检查物理边界、母线闭合、交付通道和期末硬约束。
- `model/v4_redispatch_after_compute_4_9.m`：4.6实际功率低于请求时，按“海洋需求缺口→海缆余量→同小时直通制氢→弃电”重分配释放功率。
- `model/v4_reconcile_actuals_4_9.m`：核对最终响应，并拒绝“弃电与可调电负荷缺供并存”。
- `model/test_v4_dispatch_scenarios_4_9.m`：验证额定制氢、饱和弃电和新能源骤降后的电池/算力响应。
- `model/test_v4_post_compute_redispatch_4_9.m`与`model/test_v4_terminal_path_rules_4_9.m`：分别验证响应后二次分配和期末规则。

## 与4.5的边界关系

4.9必须显式接收4.5 BOUNDARY，并只从该包读取期初电池能量、期初储氢库存、构网备用、站损、终端规则和终端目标等4.5新增参数。缺少该包会直接报错；4.9不再隐式调用4.5参数overlay，也不允许滚动窗口自行回到`cfg`初值。直接以冻结4.2配置调用4.9、同时传入完整4.5 BOUNDARY的隔离回归已经通过。

电池和储氢的逐时路径只受物理上下界约束：

- 电池路径下界为SOC物理下限叠加构网备用能量，上界为SOC物理上限；
- 储氢路径下界为0，上界为储罐容量；
- `cyclic`与`minimum/cyclic_or_minimum`只作用于窗口末点，不作为每个时段的库存下限。

电池期末后处理在保持状态递推和母线守恒的前提下，优先把已有弃电、其次把可缩减外送转为补充充电；若期末能量过高，则移除部分充电并相应增加外送或弃电。储氢期末后处理通过调整窗口内氢气交付量恢复期末目标，并重新递推整条库存路径。若启发式后处理无法满足物理边界或期末规则，4.9硬报错，不把不可行结果提交给下游。该处理是确定性可行性修复，不构成全局最优性证明。

4.6实际用电低于4.9请求时，同小时电解槽增产量与新增提氢量相等，因此“直通制氢”只吸收本小时释放的电功率，不改变原计划储氢库存路径和期末库存。
